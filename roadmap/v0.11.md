# v0.11 — the correctness stage ✅ delivered

Three defects found in the handoff code audit, each fixed against a stated
spec rather than patched. The theme: v0.10 shipped a lot of surface, and three
load-bearing mechanisms underneath it do not do what their documentation says.

Source: the audit recorded in [next.md](next.md) (the v0.11 section); the rest
of the findings stay in the backlog there.

## Decisions taken

| Question | Decision |
|---|---|
| Attempt row created when? | On **submit**, pass or fail — never at session start |
| `quit` before submitting? | Records **nothing** (no row, no lapse, no code) |
| Quitting a due warm-up? | Records nothing — a lapse is now an explicit grade 1 only |
| Resume? | Crash-recovery only; no `park` command (surface stays minimal) |
| Retention model? | Faithful **FSRS-4.5** equations + published default weights |

## Stage A — the attempt lifecycle

**Spec: an attempt row exists if and only if the student submitted.**

Today the row is inserted at session *start*, which conflates "started a
session" with "attempted a problem". Every feature-check, crash, and closed
terminal manufactures a phantom `unsolved` row — in the live DB, 8 of 15 solve
rows are `unsolved`, and the same problem was "abandoned" six times.

- The start-of-session `INSERT` is deleted; `_record_submit` creates the row on
  the first submit and updates it on every later submit in the same session.
- `quit` writes nothing. `_persist_abandoned` is **deleted**, not rewritten.
- `learn` mid-solve likewise records nothing (its retry already writes a blank
  template, so the only change is that the phantom row disappears).
- Crash-recovery resume becomes the *only* resume path — it already works,
  because the state file survives a crash. It is now load-bearing, so it is
  pinned by a test.
- `WorkbenchState.attempt_id` becomes `int | None`, set at the first submit;
  `_polish`/`_discuss` (both strictly post-submit) read it from there.
- `status` goes from mostly `unsolved` to carrying real information
  (`correct` / `wrong_answer` / `error` / `timed_out`).

## Stage B — retention

Three independent defects, three specs.

**B1 — rotation. Spec: consecutive warm-ups for a pattern serve different
problems while an unused candidate exists.** `warmup_problem` ordered *all*
correct attempts by `submitted_at ASC LIMIT 1`, which selects the problem whose
*first* solve is oldest — a value that never ages. `arrays_and_hashing` had five
solved candidates and served `array_intersection` every time. The fix aggregates
per problem (`MAX(submitted_at) ASC`), so rotation falls out of the data.

**B2 — persist the grade. Spec: every graded warm-up leaves its grade in the
learner model.** There was no grade column: `record_grade` kept only `reps` and
`lapses`, so per-pattern recall curves were unreconstructible and the reviewer
could not be calibrated against them. Adds `attempts.recall_grade` (additive
migration + `SCHEMA`).

**B3 — the model. Spec: the published FSRS-4.5 equations with their default
weights**, cited in the module docstring. The forgetting curve
`R = (1 + 19/81 · t/S)^-0.5` and the interval inversion were already exactly
correct. The update rule was not: `ease ∈ {0.6, 1.0, 1.4}` stood in for
`e^w₈ ≈ 4.44`, `(11-D)` was divided by 10, w₁₀ was 2.0 against FSRS's 0.94, and
the lapse branch was a flat `S·0.6` instead of the D/R-dependent formula — a
stability increment roughly 20× too small, which is why no card ever escaped
sub-day intervals (live cards: S = 0.36 / 0.62 / 0.75 days after 2–5 reviews).
Adopting the defaults brings per-grade initial stability (Again 0.4 / Hard 0.6 /
Good 2.4 / Easy 5.8 days), mean-reversion difficulty, the hard penalty and the
easy bonus. Pinned by a trajectory test: three good recalls at their due dates
reach at least a week.

**B4 — grade derivation. Spec: the suggestion is a prior derived from struggle,
and it can reach 1.** The old mapping was `4 if hints == 0 else 3 if hints == 1
else 2` over *all* hints, so it counted discussion questions as struggle and
could never suggest a lapse. It now counts `ladder`-kind hints only (the `kind`
was already stored) and spans 1–4. A first solve's card is seeded from the grade
its own hint count implies, instead of discarding that signal.

## Stage C — complexity measurement

**C1 — separate the instruments.** The timed call ran with `tracemalloc`
active, and tracemalloc's per-allocation bookkeeping is itself superlinear, so
allocation-heavy O(n) code measured as O(n log n). Controlled A/B on one real
solution: slope **1.164 traced → O(n log n)**, **0.889 untraced → O(n)**. New
protocol per subprocess: an untimed/untraced warm-up call, the timed call with
no tracer, then the traced space call untimed — each on a fresh `deepcopy`, so
an in-place `sort()` cannot distort later calls. The per-size repeat spread is
reported so the fit can propagate uncertainty.

**C2 — a decision rule instead of a magic number.** `NLN_SLOPE_THRESHOLD =
1.06` sat *above* the measured slope of a genuine O(n log n) function
(1.005–1.030 across four trials), so sort-based solutions were classified O(n)
every time. Replaced by: 2-parameter OLS `y = c + k·f(n)` per candidate,
compare residual sums of squares, and accept the winner only when it beats the
runner-up by more than the measured noise explains — otherwise emit an explicit
**bracket** (`O(n)…O(n log n)`). Verified achievable before adopting: on
synthetic series the RSS ratio separates n from n log n at 10% noise even with
35% constant overhead, and the real per-point spread is 3–12%. `AMBIGUITY_EPS`
and `NLN_SLOPE_THRESHOLD` are deleted.

**C3 — a three-valued comparison.** `complexity.mismatch` returned `False` for
`O(n+m)` vs `O(n²)` because neither is in `KNOWN_CLASSES`, so the three-way
table silently no-opped on exactly the multi-parameter classes that graphs, DP
and matrix problems use. Multi-parameter expressions are canonicalized
(`O(n+m) ≡ O(m+n)`, `O(n*m) ≡ O(m*n)`) and comparison returns
AGREE / DISAGREE / **INCOMPARABLE**, with incomparable axes rendered explicitly.
The reviewer now receives the ambiguity flag and R², so it stops guessing
whether a measurement is evidence.

## Test strategy

The point is to stop testing the clock.

- **Decision rule:** synthetic series, seeded, with a noise sweep asserting one
  falsifiable property — *the classifier never emits a class the data does not
  support* (brackets allowed). Deterministic, no timing.
- **Instrument separation:** mechanism-level — a solution that raises unless
  `tracemalloc.is_tracing()` is `False` during the timed call.
- **Smoke:** a thin layer of real-timing tests with bracket-tolerant assertions.
  This retires the flaky `test_linear_solution_measures_linear` rather than
  re-tuning its tolerance, and replaces the `or len(...) > 0` escape hatch at
  `tests/test_flow.py:435` with a real assertion.

## Known tradeoffs

- Abandonment is no longer recorded, so struggle now shows up in hints, tiers
  and failed submits rather than quits. The "stall detection" proposal in
  next.md must be re-derived from those signals.
- FSRS-4.5's weights are fit to item-level, day-scale, self-graded reviews;
  dojo grades a *pattern* from a hint count. The defaults are better provenance
  than hand-tuned constants, but the mismatch is real and is recorded in
  docs/retention.md rather than hidden.

## What shipped

- **Stage A** — `run_day` no longer creates a row at session start;
  `_record_submit` creates it on the first submit (any verdict) and updates it
  thereafter. `quit` and in-session `learn` write nothing; `_persist_abandoned`
  is deleted. `WorkbenchState.attempt_id` is `int | None`, and `load_state`
  ignores unknown keys so a state file written by an older dojo still resumes.
- **Stage B** — `warmup_problem` aggregates per problem and rotates; the model
  is the published FSRS-4.5 equations with default weights (one documented
  deviation: `MAX_INTERVAL_DAYS = 365`); `attempts.recall_grade` persists the
  grade; the suggestion counts only ladder hints, reaches 1, and tops out at 3;
  a first solve seeds its card from the grade its hints imply.
- **Stage C** — `measure.py` separates the instruments (untimed/untraced warm-up
  → timed call with no tracer → traced untimed space call, each on a fresh
  deepcopy) and reports its own spread; `fit.classify` replaced the R²/slope
  rule with a noise-floor plausibility rule that reports a class **or a
  bracket**; `complexity.compare` is three-valued and canonicalizes
  multi-parameter expressions.

## What was learned

- **Measured before/after is the only convincing evidence.** Replaying the 15
  stored solutions: claim-vs-measurement disagreements went 8/15 → 0/15, and the
  time slope on one real solution went 1.164 (traced) → 0.889 (untraced).
- **The identifiability limit is real, not a tuning problem.** Over this probe
  ladder O(n) and O(n log n) differ by ~0.3% of the signal variance while the
  repeat spread is 3–12%, so they cannot be separated by fit quality. The honest
  output is a range; a fixed slope threshold was always going to be wrong. A
  prototype of the rule over a 0–30% noise sweep found 0 wrong single classes
  in 2,250 trials — the property worth testing is "never claims what the data
  cannot support", not "always names the right class".
- **Two bugs in the same subsystem can cancel.** The slope threshold was
  mis-calibrated low and tracemalloc inflated the slope; together they produced
  plausible-looking output on roughly half of all real measurements. Fixing one
  alone would have made the other's damage obvious — which is itself a reason to
  fix them together.
- **The test suite was asserting the machine.** The old profiler tests pinned a
  measured class from wall-clock timing and flaked under load; `test_flow.py`
  even carried a comment tolerating the O(n)→O(n log n) flip. The rule is now
  tested on synthetic series, and the measurement on its mechanism.
- **Deleting a mechanism beats patching it.** `_persist_abandoned` and
  `complexity.mismatch` both existed only to paper over a wrong model (a row per
  invocation; unknown classes skipped). Removing them simplified the call sites.
- **Rotating warm-ups need per-problem aggregation, not new state.** The fix is
  one `GROUP BY`; the backlog item that proposed a "rotation floor" on top of
  the old query would have masked the bug rather than fixing it.
