# v0.8 — learning mode

Status: ✅ delivered — plan written 2025, implemented test-first (167 tests green).

## What shipped

`dojo learn [TOPIC]` (picker without a topic, `difflib` did-you-mean), the in-session `learn` command (parks the attempt, teaches the pattern, hands back to the same slug via the `"practice"` outcome), and the proactive offer on scheduler picks from unstudied patterns. The teacher agent (`TEACHER_SYSTEM` — topic + conversation only, may show topic-canonical code) is the documented never-solve narrowing, pinned by `test_teacher_prompt_carries_topic_only`. Transcripts persist to `learn_sessions` after every exchange; `studied_patterns` (learn sessions ∪ attempts) is the one shared notion feeding the offer and the progress markers.

Judgment calls made during implementation (defaults forced by settled principles, flagged here for review):

- **Declining a handoff stays in the conversation** — `practice` → [y/N] → "n" returns to the learn loop; `done` ends without practice (the day ends with the parked attempt for the in-session path).
- **`learn` is unavailable during warm-ups** — a warm-up is a graded recall; leaving one is a lapse via `quit`, not a pause for study.
- **Exhausted pattern** — `practice` with no unsolved curated problem in the pattern says so and stays in the conversation.

## v0.8.1 — real-session fixes

From the first live learn→practice run:

1. **Space measurement false-flagged O(n²).** `len(set(nums)) != len(nums)` is O(n) space, but peak allocations are a power-of-two staircase (set/dict table sizes), and exact-doubling sampling aliases it as exponent 2 (measured r² = 0.968). Fix: space points are classified on every-second point (`fit.staircase_safe_points`, spacing ×4) — a measurement fix, not a verdict shortcut; the synthetic staircase test pins both the alias and the fix.
2. **First review skipped (non-JSON) + 10-point-scale scores.** The reviewer prompt now states the 1–5 scale, `normalize_review` clamps out-of-range scores, and a transient non-JSON response is retried once before the review is skipped.
3. **Post-solve discussion inverted active vs. commented code.** The discussion prompt now carries the submitted code (`build_discussion_prompt`); the model grounds on what actually ran. Bonus bug found while fixing: MockBackend's discussion branch never matched `DISCUSSION_SYSTEM` (it contains "discuss", not "discussion") — keyed on "post-solve" now, pinned by a test.
4. **Prompt styling flattened on TTY.** prompt_toolkit renders no rich markup; prompts are now converted to ANSI escapes (`terminal._to_ansi`) so the bold-cyan `dojo ›` survives. Prettier AI rendering (rich Markdown + code highlighting) is tabled as a proposal in [next](next.md).

## Goals

1. **`dojo learn [topic]`** — a standalone, conversational topic primer with a practice handoff into an easy problem.
2. **In-session `learn`** — mid-solve, park the problem and teach its pattern; after learning, retry **the same slug** (a fresh attempt) — the student already read and thought about it, so a new problem would add mental load.
3. **The proactive offer** — when the scheduler picks a problem from an *unstudied* pattern, offer "learn first? [y/N]" before the session.
4. **Persistence** — a `learn_sessions` table and studied-pattern markers in `dojo progress`.

## Settled decisions

- **Park on mid-session learn.** `learn` saves progress and retires the attempt as unsolved (quit semantics); the eventual solve is a fresh attempt, so grading stays honest. The scheduler would naturally re-pick the parked slug anyway.
- **Proactive + reactive.** The offer appears only when the *scheduler* picked the problem (explicit slugs are deliberate choices); one keystroke declines.
- **The teacher may show topic-canonical code.** Never-solve protects *solves*, not knowledge: the teacher's context is topic + conversation only — never a problem statement — so implementing a heap is legitimate teaching. This is a deliberate, documented narrowing of the boundary, pinned by a guard test.
- **Store + studied markers.** Transcripts persist; no resume in v1.

## Design

### A. The teacher agent (`tutor/prompts.py`: TEACHER_SYSTEM)

- Teaches one topic from first principles to a no-formal-CS, strong-ML audience.
- Opener: a short primer — the concept, why it exists, core operations with complexity, one canonical example.
- Conversation: every student line is a message (the v0.7 bare-question convention); Socratic probes; ML/statistics analogies; humble about uncertainty ("say so when unsure" — there is no oracle for pedagogy).
- May include topic-canonical code; plain text only, short paragraphs, plain-dash lists (v0.7 conventions), `de_markdown` applied, 2048-token cap.
- Context: topic name + conversation only. Never a problem statement — `tests/test_never_solve.py` pins it.

### B. `learn_sessions` (db.py, additive)

```
learn_sessions(id, user_id, pattern, transcript JSON, created_at, completed INTEGER DEFAULT 0)
```

- `transcript`: `[{"role": "student"|"teacher", "text": ...}]`; persisted after each exchange (crash-safe).
- Helpers: `record_learn_session(...)`, `studied_patterns(conn, user_id) -> set[str]` (any learn session **or** any attempt in the pattern), `unstudied(conn, user_id, pattern) -> bool` — one shared notion for the offer and the progress markers.

### C. `dojo learn [topic]` (cli)

- No topic → numbered picker over `PATTERNS` (generalize the `dojo user` picker into a shared `_choose`); unknown topic → "did you mean …" via `difflib`.
- `run_learn(conn, console, backend, user, pattern, handoff_slug=None)`:
  - primer (one call) → loop: bare line = message; `practice` → handoff; `done`/`quit` → end.
  - Handoff: `handoff_slug` given (in-session path) → "retry `<slug>`? [y/N]"; standalone → pick the easiest unsolved curated problem in the pattern → offer. Accepted → return `{"practice": slug}` (the caller starts a normal blank-template session).
- `learn` joins `USER_COMMANDS`.

### D. In-session `learn` (flow)

- `COMMANDS_HINT` gains `learn`. Bare `learn` teaches the current problem's pattern; `learn <topic>` teaches another topic but still parks the current attempt (handoff targets the parked slug either way).
- Parking = the quit persistence (code + hints, status unsolved) with a learn-specific message, then retire state, then `run_learn(handoff_slug=slug)`.
- Control flow: `run_day` returns `"practice"` when the handoff is accepted (state retired); `_cmd_day` loops `while outcome == "practice": run_day(same slug)`; `run_warmups` treats `"practice"` like quit.

### E. The proactive offer (cli `_cmd_day`)

- After the scheduler pick, when `slug is None` (deliberate picks are exempt): if `unstudied(conn, user_id, problem["pattern"])` → "This is from 'heap' — a pattern you haven't studied. Learn it first? [y/N]" → on `y`, run_learn with that pattern and the picked slug as handoff; either way, proceed into the session afterward (the offer is a fork, not a gate).

### F. Tests (offline)

- MockBackend gains a `teacher` canned queue (`"teacher" in system` branch, ordered before `"tutor"` — TEACHER_SYSTEM avoids the word "tutor").
- `tests/test_learn.py`: run_learn happy path (primer, exchanges, transcript persisted, completed flag); bare-line-as-message; practice handoff result; studied/unstudied logic; picker + did-you-mean; in-session learn parks the attempt (row unsolved with code, state retired, learn session recorded, "practice" outcome); never-solve guard (teacher prompt carries topic only).

### G. Docs

README (learn command + offer + boundary note), docs/architecture.md (learning-mode section with the boundary-narrowing rationale), AGENTS (teacher protocol; never-solve rule 1 amended with the documented narrowing), roadmap index.
