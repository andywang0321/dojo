# v0.9 — onboarding: minimal help, new-user README, key detection

Status: ✅ delivered.

## Goals

1. **Radically simplified help.** `dojo help` = `dojo -h` = `dojo --help` (intercepted in `main` before argparse) prints a hand-written guide: bare `dojo` usage + the seven everyday commands (`learn`, `list`, `progress`, `history`, `fetch`, `user`, `setup`). Power tools stay dispatchable but never listed: `day`, `warmup`, `check`, `show`, `curate`, `report` — and `profile`, which became a hidden alias of `history` (audit proposal 4: one review surface). Each still documents itself via `dojo <cmd> --help`.
2. **New-user README.** Rewritten around the actual first-run path: prereqs, `git clone` → `uv run dojo` → wizard → plain `dojo`. Explicit that you run from a checkout; the wizard is described step by step; the mock-backend escape hatch is up front.
3. **Setup key detection.** `run_wizard` resolves the key as environment → dotenv → prompt. A detected key skips the prompt (and an env-sourced key is persisted to the dotenv so every shell sees it); `--skip-key` disables detection too, so scripted installs (`make seed`) never write a key.
4. **Ergonomic pre-wrapper start.** The answer to "how do I start before `dojo` exists" is documented as the only command: `uv run dojo` (uv builds the project env automatically — no `make` needed). The wizard's closing line now points at `uv run dojo` when the PATH install is declined.

## Lessons

- argparse's `help=argparse.SUPPRESS` prints `==SUPPRESS==` literals on Python 3.13 — hiding lives in the interception, not the parser.
- The env-detection tests pin `detect_env_key=False` on the prompt paths: a keyed ambient environment must never make them flaky (determinism rule 5).
