# v0.2 — the retention engine

**Shipped:** FSRS-lite spaced repetition (`pattern_cards` with stability/difficulty, forgetting-curve intervals), warm-up retrievals (re-solve from scratch, recall grade, quits record a lapse), weakest-pattern problem picking, card backfill from v0.1 history, `dojo warmup` and `dojo progress`.

**Hardening within v0.2 (later commits):**

- **Session lifecycle fix** — workbench state is retired on submit/quit; one invocation = one attempt row; repeat sessions can never overwrite history. Quitting persists code + hints.
- **Blank templates + `dojo history` / `dojo show`** — every session starts fresh; past attempts are fully recoverable.
- **The interview corpus re-homed** — ten *Ace the Data Science Interview* problems sorted into pattern directories with rewritten prompts (new patterns: trees, heap, binary_search, greedy, dynamic_programming, math).
- **Full-bank curation** — 31/31 problems curated (visible tests, signatures, oracles, generators, profiler inputs).
- **Judge verdict modes** — per-case comparators (`sorted`, `approx`, `rounded`, `predicate`, `ops`) so "any order" contracts are honored instead of pinned; class/multi-function/predicate problems became curatable.
- **The AI curator** — `dojo curate` proposes, validates, applies with a verification gate and rollback.

**Lessons:** the attempt-overwrite bug (state reuse silently clobbering the declared learner-model asset) showed the asset claim needs lifecycle tests, not intentions. The curation contract tests (`tests/test_registry.py`) became the machine-checkable backbone everything later builds on.
