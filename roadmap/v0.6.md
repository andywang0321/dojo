# v0.6 — practice-run polish

Status: delivered. Triggered by the first real solve-and-review session.

**Shipped:**

- **Static analysis at check time** — advisory ruff/radon findings appear with every `check` (live coaching loop); submit still stores them and feeds the reviewer. The style score grades the final code — the trainer, not the exam.
- **The post-solve loop** — after review + reflection: `polish` (re-judge + re-measure + re-analyze the edited code, updating the same attempt row, `polished` counter bumped, optional second review), `discuss <question>` (free post-solve chat, never-solve boundary lifted, transcript persisted), `done` (retire).
- **The reviewer engages with reasoning** — reflection now happens *before* the review; the rubric gains `complexity_reasoning` (is the why sound?) and `reflection_feedback` (prose, not a score). Model output is schema-normalized (`normalize_review`) — a real solve had returned bare ints and rendered an empty chart.
- **Tutor modes** — one `hint` command, AI-classified: ladder (stuck, tiers advance) vs discussion (exploring, no tiers, honest labels). The leak audit hardened: a response still rated ≥ 3 after retries is discarded, never shown — the practice run had surfaced two such leaks displayed with a badge.
- **Ergonomics** — command order is now `open · check · hint · submit · quit`; the complexity prompts lost their example suffix.

**Lessons:** a single real session out-teaches weeks of design: the tier system was narrating a struggle that wasn't happening, the leak audit was showing its own failures, and the reviewer's schema was trusted without validation. All three are now pinned by tests.
