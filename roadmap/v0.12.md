# v0.12 — the measurement stage ✅ delivered

The v0.11 profiler measures a solution's cost curve **in isolation** and fits an
absolute complexity class. The audit that preceded this stage established, with
numbers, that this cannot work: over a feasible probe ladder O(n) and O(n log n)
differ by ~0.3% of the signal variance while the real per-point spread is 3–12%,
so the honest output was a bracket — which is not useful enough to be worth the
machinery.

v0.12 stops asking the unanswerable question. The profiler becomes a **scale
probe against a reference implementation**:

- run the student's code at increasing sizes and **report failure loudly**
  (it is the only place in dojo that runs user code above n≈12 — and it silently
  swallowed a `ValueError` that the AI reviewer then scored 5/5);
- compare its cost **against the canonical solution's**, measured interleaved on
  the same inputs, which cancels the constant-factor ambiguity that made the
  absolute fit unusable;
- derive the student's class *relative to the reference* instead of fitting it
  from scratch, and say "could not resolve" when even that is unsupported.

Source: the design conversation recorded in [next.md](next.md).

## Decisions taken

| Question | Decision |
|---|---|
| Absolute class fitting (`fit.py`) | **Deleted.** Replaced by ratio analysis against a reference |
| Where does the reference come from? | The curator writes it; it is admitted only if it agrees with the brute-force oracle |
| Does it replace the oracle? | No — two artifacts, two roles: the oracle is the trust anchor, the reference is the performance/scale baseline |
| Machine learning / numpy / `big_O`? | No. Same method, same ceiling, and it would remove the honesty features |
| Cross-platform "would this TLE?" | Not claimed. The verdict is **relative to the reference** plus absolute times, never a predicted platform outcome |
| Fuzzing with shrinking | Deferred to v0.13; v0.12 compares outputs at probe sizes and localizes the smallest failing size |

## Why a reference is the missing piece

The oracle is *deliberately* brute force (`curator/prompts.py`: "Prefer a simple
brute-force reference"), and that is right for its job — but it means the oracle:

- **cannot validate anything at scale** (O(n²) at n=10⁵ is impossible);
- **cannot be a performance baseline**, because it *is* the slow thing
  (`products_of_array_except_self`'s oracle is an O(n²) double loop while the
  problem targets O(n)).

So the scale test and the budget both need a *fast* reference, and the only
source of one is the model's recall of the canonical solution. That is a good
use of recall: a canonical solution is **mechanically verifiable** (does it agree
with the brute-force oracle on every generated case?), unlike a complexity
judgement, which is not checkable at all.

## Architecture

```
profiler/
  probe.py    # run a PAIR of targets at a ladder of sizes, interleaved;
              # per size: wall time, peak bytes, exception, output digest
  growth.py   # ratio trend between the pair -> a class RELATIVE to the reference
```
`measure.py` and `fit.py` are deleted — including `staircase_safe_points`, whose
problem is now solved by construction: a staircase in the container sizes appears
in *both* curves and cancels in the ratio.

**Probe protocol**, per (size, repeat), one subprocess per target, interleaved:

1. an untimed, untraced warm-up call;
2. **the timed call with no tracer running** — and with the argument copy made
   *outside* the timed window (v0.11 put it inside: at n=6400 the deepcopy was
   0.769 ms of the 1.005 ms reported, i.e. 76% of the "algorithm time" was the
   profiler's own bookkeeping);
3. the space call with `tracemalloc` active, untimed;
4. the result is reduced to a digest so a mismatch can be detected without
   shipping megabytes back.

An exception or timeout is **data**, not a void: the probe reports it with the
size and the message, stops ascending (bigger is pointless once it breaks), and
skips the remaining repeats of a timed-out size.

## Stage A — the probe and the verdict

**Spec:** given a student target, an optional reference target, and a ladder,
produce (i) the smallest size where the student failed and why, (ii) per-size
paired ratios, (iii) a growth verdict.

The verdict is *relational*: `matches` / `worse` / `better` / `unresolved` /
`failed` / `unreferenced`, with a signed step count and the trend. Classes are
used only to **name** an observed ratio: the expected trend for a candidate class
`f` against the declared class `g` is `(f(N)/f(n₀)) / (g(N)/g(n₀))`, so a
declared-O(n) reference gives expected trends of 1.0 (O(n)), 1.9 (O(n log n)),
64 (O(n²)), 4096 (O(n³)) over the default ladder. The observed trend is matched
to the nearest expected value in log space; nothing is least-squares fitted and
no R² is produced.

**Tests:** synthetic ratio series for every verdict outcome (deterministic, no
clock); mechanism tests for the timed window (no tracer; a constant-work function
measures flat regardless of input size, which the in-window copy would break);
interleaving cancels a common-mode drift injected into both targets; a synthetic
staircase pair yields "matches".

## Stage B — the reference artifact

**Spec:** a canonical reference exists per problem, and it is admitted only when
it is *proved equivalent to the trust anchor*.

- `judge/registry.py` gains `@reference(slug)` / `REFERENCES`, alongside the
  oracle. Reference code must be self-contained (the gate executes it in the same
  isolated namespace the curator uses).
- The curator proposal gains `reference_code`, validated to compile, and the
  apply gate refuses a reference that disagrees with the oracle on any generated
  case or visible test — the same dual-check that already gates the oracle, now
  applied *between two different kinds of artifact*, which is strictly stronger
  than two samples of one prompt.
- `dojo reference [slug|--all]` generates and gates a reference for an existing
  curated problem (backfill), with rollback.
- The `dojo report` audit gains two dimensions: reference-vs-oracle disagreement,
  and **generator value-range fidelity** (the `products_of_array_except_self`
  case: values up to ±20 at n=6400 drive the running product to ~19,000 bits,
  violating the problem's own 32-bit guarantee and making a correct O(n)
  solution genuinely superlinear).

## Stage C — the session wiring

- `_measure_complexity` becomes one probe call; the table's third column becomes
  the relational verdict plus the trend ("1.1× the reference"), replacing the
  R² column (there is no fit to report).
- A scale failure is printed as a first-class finding, with the message and size.
- No reference → explicit degradation ("no reference registered for this problem
  — the growth check is unavailable; `dojo reference` adds one"), never a silent
  fallback to the absolute fit that was deleted.
- The reviewer receives the verdict and the failure, so it stops treating a
  measurement it cannot see as evidence.
- Persistence: `measured_time_class` holds the **derived** class (what the
  differential concluded) and a new additive `measurement` JSON column holds the
  full verdict and points. The `measured_*_r2` columns stop being written and
  stop being displayed.

## Stage D — correctness at scale

Comparing outputs is nearly free once both targets already run at every size:

- at each probed size, compare the student's digest with the reference's, using a
  per-problem `scale_compare` mode (`strict` by default; `sorted` for
  order-insensitive answers — the audit flags problems whose judge cases use a
  looser comparator while `scale_compare` is strict);
- on a mismatch, localize the **smallest failing size** by probing below it;
- confirm against the brute-force oracle at that size when it can run: oracle
  agrees with the reference → the student is wrong; oracle agrees with the
  student → the reference is wrong (a curation fault); neither → report it as
  unconfirmed and point at `dojo report`.

That decision procedure is what keeps a false failure — the worst outcome for
trust — from reaching the student.

## Test strategy

Same shape as v0.11 and for the same reason: **the decision logic is tested on
synthetic data, and the measurement is tested on its mechanism.** No test asserts
a complexity class from wall-clock timing. `tests/test_fit.py` and
`tests/test_profiler.py` are replaced by `tests/test_probe.py` (mechanism +
synthetic ratios) and the reference tests.

## Known tradeoffs

- A reference puts more model-written code into the trust path. The gate is the
  mitigation: it must agree with the brute-force oracle everywhere the oracle can
  run.
- The never-solve blast radius grows: a canonical solution is directly
  paste-able, whereas a brute-force oracle often is not a passing submission.
  Strengthening the never-solve guard test (next.md #2) becomes a prerequisite
  rather than a nicety.
- Problems without a reference degrade to "durability at scale" only. Backfilling
  needs an API key.
- Comparing outputs at scale needs the problem's comparison semantics; a
  mis-tagged problem would produce false failures, which is why the audit checks
  it and why an unconfirmed mismatch is reported as a curation question rather
  than as a verdict on the student.

## What shipped

- **`profiler/probe.py`** — the paired scale probe: student and reference
  interleaved at each size, one subprocess per (target, size, repeat), reporting
  time, peak memory, the result digest, and any exception or timeout. `measure.py`
  and `fit.py` are **deleted**, including `staircase_safe_points` (a ratio carries
  the same container staircase on both sides, so it cancels).
- **`profiler/growth.py`** — the ratio trend becomes a class *relative to the
  reference*, with `unresolved` as a first-class answer.
- **`judge/registry.REFERENCES`** — the canonical-solution registry, plus five
  hand-written references to make the feature live (including
  `products_of_array_except_self` and `top_k_frequent_elements`, the two problems
  that motivated the stage).
- **`curator.reference_findings` / `add_reference`** and `dojo reference
  [slug|--all]` — generation, the oracle gate, and install; `apply()` carries a
  reference through for new problems.
- **`judge/compare.py`** — the judge's verdict semantics extracted from the
  harness string so the reference gate judges by exactly the same rules.
- **`flow.Measurement`** — one probe call per submit, failure and mismatch
  reported as first-class findings, the derived class persisted in
  `measured_*_class`, the full record in the new `attempts.measurement` JSON.
- **`tests/test_prompt_routing.py`** — every system prompt must reach its own
  canned branch, after the reference prompt silently shadowed the curator's.

## What was learned

- **Measured before/after on the two real cases.** `products_of_array_except_self`
  (attempt 30, correct O(n)): ratios 1.33, 1.25, 1.07, 0.94, 1.03 → *matches the
  reference, consistent with O(n)*, where v0.11 reported `O(n)…O(n³)` and
  red-flagged it. `top_k_frequent_elements` (attempt 28): *your code failed at
  n=100: `ValueError: Not enough elements!`*, where v0.11 stored NULL columns and
  the reviewer scored the same code 5/5 on correctness.
- **A ratio is immune to constraint-violating probe inputs.** The
  `products_of_array_except_self` generator still drives the running product to
  ~19,000 bits at n=6400, which makes the *problem* genuinely superlinear — but
  both implementations pay it, so the ratio stays flat. The differential design
  absorbs a curation bug that the absolute fit reported as a finding about the
  student.
- **The two symptoms that looked like "too much uncertainty" were mostly bugs.**
  The invalid probe input was a curation fault, the NULL columns were a swallowed
  failure, and a third was self-inflicted: v0.11 timed the argument copy, which at
  n=6400 was 0.769 ms of the 1.005 ms reported.
- **The right question was not "what class is this?".** Asking whether the code
  grows like the *intended solution* is (a) answerable from paired measurements
  where the absolute fit is not, (b) the question an interview actually asks, and
  (c) checkable against an artifact the model is good at producing and the oracle
  can falsify.
- **Reference authoring needs the tie-break, not just the algorithm.** The first
  `top_k_frequent_elements` reference was refused by the gate for ordering; the
  gate's strictness is the feature working, since the probe compares the student
  against that baseline.
- **A prompt phrase can silently steal another agent's branch.** Adding
  "canonical solution" to the curator prompt made the mock serve reference
  payloads to `dojo curate`. `tests/test_prompt_routing.py` now pins which branch
  each prompt reaches.
